# Jev Mobile 可验证创新方向调研

调研日期：2026-10-19。范围：当前项目源码以及移动和桌面 GUI Agent 的相关原始论文。性质：探索性先验工作扫描和研究设计，不是系统综述，也不是已完成的实验论文。

## 结论

建议优先研究：**系统何时应该补充观测，以及补充哪一种观测，才能以较低总成本修复结构化执行。**

具体落点是分别估计“当前候选动作集合是否足以支持任务继续”和“各补救方式实际能带来多少收益”，再决定继续 Jev 执行、刷新控件、请求一次视觉帮助或完整视觉接管。不能把简单的置信度阈值切换包装成这个方法。

第二方向是动态页面下的选择性重验证与目标重新绑定。第三方向是区分“目标状态已经存在”和“本次操作产生了新结果”的完成证据。第二和第三方向均有很近的已有工作，适合作为支持模块或另立选题，不建议一次全部堆进首篇论文。

**目前只能确认相关先验工作和可检验的技术差异，不能确认候选方案已经形成原创贡献。**没有新实验结果，也没有速度、成功率或风险保证的实测提升。以下创新判断都是研究假设；需要与强基线比较才能成立。

## 1. 首先需要处理的直接近邻

Linghua Zhang 的 [Jev-Mobile: Jev as an Executor for Mobile GUI Agents，arXiv:2609.30186v1](https://arxiv.org/html/2609.30186v1) 已于 2026-09-24 提交。用户已明确确认：与该论文无关系。

其方法是 VLM 给局部目标，Jev 在 A11Y 候选中连续选择动作，再交回控制权。正文 §2–3 还区分候选覆盖、候选选择和控制权交接。其 v1 明确不从图像补出缺失的坐标动作。因此，“Jev 加视觉模型”和“区分缺目标与选错目标”都不能单独作为本项目的新贡献；研究应进一步落实到可学习的补充观测策略及闭环验证。

两个项目的名称也高度接近。后续论文应选择区分度更高的标题，明确引用并比较该工作。本文不判断双方代码来源，亦不将其结果当作本项目结果。

## 2. 当前项目具备什么，还缺什么

以下结论来自源码审阅，未在本次调研中重新运行手机任务。

| 当前实现 | 对研究设计的影响 |
|---|---|
| `agent.py::_handoff` 是规则触发的单向 fast→vision，异常和循环等情况触发接管 | 可以加入补充观测选择和短暂咨询，但“双向切换”本身不足以构成创新 |
| `model.py::choose` 返回操作和目标相关分数 | 分数不是校准过的真实动作成功概率；正确目标未进候选表时仍可能高置信度选错 |
| `a11y.py` 有候选筛选和 `MAX_ELEMENTS=250` 限制 | 候选不足既可能来自系统树，也可能来自本项目处理过程，需要分开统计 |
| `device.py::_observe_visual` 并行读取图像和树并检查焦点 | 检查焦点并不等于图像与树来自同一时刻；同一窗口也可能发生布局变化 |
| `device.py::fresh_index` 有整张语义表的有效性比较；视觉 fast 按既定配置跳过执行前核对 | 已有“严格检查”和“完全不检查”两端基线，可以研究二者之间的成本收益 |
| `vision.py` 已向完成复核提供前后观察和历史信息 | 不能把“增加前后图复核”当作新功能或新贡献 |
| Bridge 写请求在响应不明时已避免盲目重新提交 | “超时后不要重复写”已有局部实现，若研究必须上升到跨恢复阶段的证据协调 |
| `aw_agent.py` 提供 AndroidWorld 接口，但未覆盖完整视觉恢复链 | 正式评测需要接通完整方法；统一观察、动作和等待预算，避免接口差异主导结果 |

最值得关注的现有失败模式是：**模型在一个不够用的候选集合里自信地选择动作，直到多次失败才升级。**局部全屏变化也不等于任务进展，不能直接作为正确性标签。

## 3. 不能再作为独立创新的常见部件

| 想加的部件 | 直接相关先验工作 | 对本项目的结论 |
|---|---|---|
| 低置信度调用更大模型 | [AVR](https://arxiv.org/html/2603.12823v1) §3 | 可以作为基线，不能仅靠换模型名形成贡献 |
| 不确定性校准和高风险时拒绝动作 | [SafeGround](https://arxiv.org/html/2602.02419v2) §3–4 | 校准有价值，但要证明本项目解决了不同的决策问题 |
| 结构化定位不确定时请视觉模型局部裁决 | [SAGE-GUI](https://openreview.net/pdf?id=QnbXZ0JmP9) §3.4 的检索索引片段 | 与“看一眼再回快模型”高度接近，必须作为近邻继续核对 |
| 执行前检查局部图像是否过期 | [Temporal UI State Inconsistency / PUSV](https://arxiv.org/html/2604.18860v1) §5 | 局部补看图和 TOCTOU 检查已有方法 |
| 图像与结构不一致时重新定位 | [Do GUI Agents Believe Their Eyes?](https://arxiv.org/html/2607.04334v2) 的缓解方法部分 | 跨模态一致性检查不是空白领域 |
| 失败后保留状态并切换执行方式 | [OctoNest](https://arxiv.org/html/2606.20487v2) §2 | 状态交接和局部恢复属于已有研究方向 |
| 完成时主动找证据或查看历史截图 | [VAGEN](https://arxiv.org/html/2602.00575v2) §3.3–3.6 | 前后图加主动验证不足以单独支持原创性 |
| 分解里程碑并审查证据链 | [OS-Themis](https://arxiv.org/html/2603.19191v1) §3 | 增加多个评审角色不等于新方法 |
| 轨迹记忆和部分步骤复用 | [DeltaReplay](https://arxiv.org/html/2610.11707v1) §3 | RAG 和轨迹图不宜作为主创新 |
| 故障注入与恢复基准 | [GUI-RobustEval / RoTS](https://arxiv.org/html/2605.29447v1) §2 | 不能声称首次评测 GUI 错误恢复 |

AVR 的 CUA 成本结论包含从其他任务推演的部分，不能直接当作本项目可期待的闭环实测收益。SAGE-GUI 的直连全文遇到访问验证，本次只使用其原始 PDF 搜索索引可见的方法片段；作者、明确版本和评审状态未确认，不把它作为已全面审读的论文。

## 4. 优先方向：面向候选充分性和实测收益的补充观测策略

### 4.1 通俗解释

用户要点“发送”，控件树却漏掉了发送按钮。Jev 只能在已有选项中挑选，可能以 0.96 的置信度点中另一个控件。这个 0.96 不能回答“正确按钮有没有被系统看到”。

拟增加的控制模块要分别回答：

1. 现有信息和候选动作，是否足以让任务正确前进？
2. 如果不够，刷新控件表、问视觉模型一次或完整接管，哪一种补救更划算？

例如只需要视觉模型识别一个 A11Y 没有提供的关闭按钮时，可以请求一次坐标帮助，执行并重新观察，然后恢复结构化执行。若页面需要理解图片内容或复杂视觉推理，则保留完整视觉接管。

### 4.2 研究方法应该具体到什么程度

令 `C_t` 为当前可执行候选集合，`G_t` 为独立标注的可接受下一步动作集合。候选充分性标签可定义为 `C_t` 是否包含至少一个适用于当前任务的可接受动作。`G_t` 可以有多个动作，不能把唯一示范点击当作全部正确答案。对“必须看图才能读出内容”的情况，还要标注信息不足，而不是只标注按钮缺失。

建议首先预测两类量：

- 当前信息足以支持正确继续执行的概率。
- 针对刷新、单次视觉咨询和完整接管，各自相对当前策略的预期任务收益及附加耗时。

控制器选择受预算约束的动作。第一版可以使用逻辑回归或小型树模型，先检验问题是否成立，再决定是否需要复杂网络。

可使用的在线特征包括任务与候选文本的匹配、候选数量、标签缺失比例、重复标签、动作分数间隔、近期动作结果和观察年龄。这些都只是统计信号。若额外使用缩略图或视觉编码，其获取和推理成本必须计入，不能假装是免费输入。

**不可识别性边界：**如果两个真实页面向控制器提供完全相同的信息，而一个页面遗漏了正确目标，单靠这些输入不可能可靠区分二者。模型只能给出经验概率；要降低这类盲区，需要有成本的抽样视觉检查或其他补充观测，不能宣称从控件置信度就能知道所有缺失。

### 4.3 如何获得真实监督

在可重置的模拟器或测试 App 中，从同一个初始状态分支运行不同方案，固定模型版本和预算，记录各分支的外部判定结果及完整成本。不能拿不同任务的平均成功率来标记某次视觉咨询是否有用。

训练样本覆盖自然 A11Y 缺失以及受控的候选删除、标签损失和歧义。必须加入候选数量相同的干扰对照，防止模型只是学会“候选变少就是出问题”。同一页面派生出的所有扰动放在同一个数据划分中；测试保留未见 App 和任务模板，避免泄漏。

单次视觉咨询的结果应包含本次观察标识、动作目标和必要事实，作用范围限于当前观察。它不会产生跨页面永久有效的坐标或编号。重新进入 fast 需要依据动作后观察，而非视觉模型自述“修好了”。加入有限咨询预算和切换滞回，避免模式来回抖动。

### 4.4 与近邻真正不同的部分

AVR 侧重动作由哪个模型处理，SafeGround 侧重预测可靠性，SAGE-GUI 已有结构定位后的视觉裁决，同名 Jev-Mobile 已指出候选覆盖问题。因此可尝试的差异是：**用同状态分支获得的实际收益监督，联合选择补充观测方式与控制权范围，并在候选不足但分数很高的状态下验证效果。**

这是一项组合机制的研究假设，不是“首次提出视觉咨询”。只有在相同模型和成本预算下超过上述思路的合理实现，才有资格作为贡献。

### 4.5 必须做的对照和否证

至少比较：当前规则接管、全程视觉、校准置信度阈值、候选健康度简单规则、SAGE-GUI 风格局部视觉裁决，以及拟议策略。固定底层模型、动作空间、任务重置和最大步数。必要时加入用小型 VLM 替代 Jev 的同流程对照，区分策略收益与特定服务收益。

消融分别去掉充分性预测、实际收益监督和咨询后返回 fast。报告端到端成功率、错误动作率、延迟 P50/P95、模型费用、强模型调用数，以及缺失目标状态下的识别能力。统计全部尝试，另外再提供成功轨迹条件下的延迟；不能只展示成功且很快的样本。

**淘汰条件：**如果校准置信度加简单候选规则在相同预算下已经达到同等表现，或收益仅存在于人工删除候选的数据而不能迁移到自然缺失，则该机制不应继续被宣传为论文主贡献。

## 5. 第二方向：依据目标和预算决定重验证，并重新绑定目标

### 5.1 要解决的实际矛盾

当前完整表比较可能因与目标无关的页面变化而作废决策，完全跳过核对又会使用过期目标。例如模型推理期间软键盘弹起，“发送”按钮位置改变，但任务意图和按钮身份没有变。

拟研究的模块保存目标的语义身份和观察时间，在必要时对新树中的目标重新匹配；只有唯一、可见且可操作的匹配才能继续。多个“删除”或多个“发送”不能只按同名猜测，需要限定会话、容器或其他可观察上下文。目标消失或冲突则重新观察。

### 5.2 已有方法与窄差异

PUSV 已有执行前局部图像、全局变化和窗口核对；Pixels-versus-Structure 工作已有一致性检查及重新定位。因此“检查目标附近”以及“发现不同就重定位”不新。

值得验证的是：**以观察年龄、变化事件和动作后果为依据选择检查强度，并在良性位置变化时保留语义目标，减少整轮重新请求。**目标是同时降低误点和无效中断，不能靠全部拒绝动作获得漂亮的安全数字。

测试应包括目标移动、目标被替换、无关动画、键盘展开、同名按钮和延迟增加。比较完整表守卫、无守卫、PUSV 风格局部检查、固定语义重新绑定以及自适应方案。

这更适合作为方向一的执行层支持。如果只写出一个资源 ID 匹配函数，而没有新的选择策略和优势证据，应称为工程改进。

**边界：**截图、读树和跨 App 的点击不是一个原子事务，检查结束后页面仍可能变化。不能承诺完全消除 TOCTOU，也不能保证坐标对应的隐藏业务语义不变。本次只提出研究方案，不改变用户既定 fast 模式的行为。

## 6. 第三方向：识别本次任务的新结果，并协调不确定的动作结果

### 6.1 为什么和现有复核不同

“打开蓝牙”可以因蓝牙已经开启而满足；“再给王鑫发一次你好”必须证明本次产生了新的发送事件。聊天记录里已有相同气泡，只能证明过去发生过，不能直接证明本次完成。

当前系统已有前后图复核。拟议增量是显式区分状态目标与事件目标，并记录动作提交和结果证据的关系。对回包丢失的写动作，保留“结果未知”，先检查是否已经生效，再决定继续或终止，避免恢复流程重复执行。

可记录本地动作标识、目标身份、提交前证据、是否已派发以及派发后可观察变化。动作标识只是追踪工具，不代表第三方 App 支持幂等提交。

### 6.2 为什么不能轻易声称创新

VAGEN 已研究按成本逐步查看历史和主动取证，OS-Themis 已审查里程碑证据链。本项目 Bridge 也已经对部分不明结果避免盲目重试。

因此候选贡献应限定到：**状态目标与新事件目标的区分，在回包不明与已有相似成功证据同时出现时，如何以较少观察降低错误完成和重复副作用。**必须与现有双图复核及主动验证方法比较。

构建旧成功气泡、输入框有文字但未提交、回包丢失但已提交、未提交且回包丢失等配对案例。评估错误 DONE、重复操作和证据不足时的正确保留不确定性，同时报告真实完成率与附加时间。

若界面没有可区分的新证据，应保留不确定，而不能编造“恰好一次”的保证。可见的己方消息气泡通常支持已提交到聊天界面的判断，不能据此直接声称对方设备已送达或已读。

## 7. 共同需要的评测部件

建议做一个针对本项目的可重置故障评测扩展，而非仓促宣称新通用基准。

| 受控因素 | 隔离的问题 | 独立真值 |
|---|---|---|
| 只改变候选表示，真实界面不变 | 候选充分性与选项选择的区别 | 测试环境的可接受动作集合 |
| 图像和树来自不同时间点 | 观察不同步 | 捕获时间与已知 UI 状态序列 |
| 推理期间移动或替换目标 | 动作前失效与重新绑定 | 测试控件身份和事件记录 |
| 动作生效后丢弃响应，以及生效前失败 | 结果不明时的恢复 | 测试 App 的独立提交计数 |
| 初始状态存在相似的历史成功证据 | 新事件与已有状态混淆 | 初始快照和最终提交差分 |

外部真值只能给评测器，不能作为智能体额外输入。对代理实际没有任何可见区别的案例，不应要求它凭空识别隐藏状态；应评价是否避免武断声明、是否有合理的取证或退出行为。

[GUI-RobustEval](https://arxiv.org/html/2605.29447v1) 已评测策略错误后的恢复。[SSCBench](https://arxiv.org/abs/2610.11514) 讨论故障注入测试的证据有效性。这里可争取的差异是分离观察、动作和传输故障，并明确反证何时可被代理看到；“加故障注入”本身不是创新。

## 8. 最小研究路线

1. **先验证问题规模。**用一批可重置任务统计高置信度错误中，有多少源于候选不足，多少源于选错，多少源于观察过期。人工标注多种可接受下一步动作，对无法确定的样本保留不确定。若候选不足在真实任务中很少出现，先调整主问题。
2. **建立强基线。**先跑当前规则、全程视觉、校准置信度和固定局部咨询，统一底层模型与动作预算。先导样本可用 20–30 个任务，每任务重复若干次，仅用于发现问题和估计方差，不作为正式充分证据。
3. **采集同状态分支数据。**在模拟器快照上比较几种补救的真实收益。训练、验证和测试按 App 与任务模板隔离，合成扰动与自然失败分别报告。
4. **只实现方向一的最小控制器。**先判断是否需要补充信息，再选择刷新、咨询或接管。为每次决策留下成本和依据，避免增加多个 LLM 角色。
5. **扩大正式闭环评测。**覆盖完整任务而不止单步定位，清洁场景和扰动场景同时运行。按任务簇计算配对差异及不确定区间；正式样本量根据先导方差和预先选定的最小有意义差异设计。
6. **依据否证结果决定论文。**机制有效再补方向二的执行保障；方向三只有在完成误判确为主要瓶颈时另做。所有实验失败都计入结果，不用增添部件掩盖主机制无效。

底层 Jev 是远端黑盒 API，目前代码无法访问它的权重、隐藏状态或 KV Cache。不要把训练 Jev、内部 MoE 路由或复用服务端 KV 作为可直接落地的最小方案。控制器可以独立训练，但要记录 API 版本变化、观察成本及模型调用成本。

## 10. 自我审查与建议取舍

- **最大原创性风险：**方向一退化为 SAGE-GUI 的视觉裁决加上普通模型路由。应把可学习的补充观测收益和真实候选不足作为核心实验，不能只画不同架构图。
- **最大有效性风险：**合成候选删除很容易做出漂亮结果，却不能代表真实手机失败。必须保留自然缺失和未见 App 测试。
- **最大效率风险：**为了省视觉调用，反而每步加一轮 LLM 路由。应优先使用无需额外大模型请求的控制器并计入全部开销。
- **最大统计风险：**只统计成功轨迹的速度，或把同一页面的多个扰动当成独立样本。应完整报告分母并按任务或 App 成簇分析。
- **最大主张风险：**把效果尚未验证的设计叫作创新成果。论文现阶段应写研究问题和假设，不能写已提升成功率。

推荐首篇围绕一个问题组织：**什么时候值得补看图，补看之后应该继续结构化执行还是转交控制权？**实现一个可解释的控制器，配套一个有独立真值的受控评测扩展。方向二作为需要时的执行层支持，方向三保留为独立备选。
